## Failure report format

When a test fails, report:

```
✗ LLMV-API-032 — Concurrent run-analysis calls (double-charge race)
  Class   : API bug
  Expected: exactly one credit deduction row
  Actual  : two rows in credit_usage table
  DB diff : SELECT * FROM credit_usage WHERE project_id = '...' → 2 rows
  Action  : file ticket, do not auto-fix without confirmation
```

Failure classes: `API bug` · `UI bug` · `DB mismatch` · `test bug`

## Absolute rules — never break these

1. **Never write to the database.** Read-only means SELECT only. No INSERT, UPDATE, DELETE, TRUNCATE under any circumstance.
2. **Never run `run-analysis` on a production project without explicit confirmation** from Malka. It consumes real Universal Credits.
3. **Never commit `.env.db` or `auth-state.json`.** Both are in `.gitignore`.
4. **Never invent test IDs.** Use only IDs from the uploaded suite files.
5. **Never run Suite A in parallel.** Workers must be 1 for `tests/api/`. Credit-integrity cases break under parallelism.
6. **Phase 0 must run before Suite DB.** `config/schema-map.json` must exist and be populated before any DB-010+ case runs.
7. **Twingate must be active** before any DB suite run. If `postgres-llmv` cannot resolve, stop and tell Malka.

## Auth

Session is saved to `auth-state.json` by running:
```bash
npm run auth:save
```
All suites inject it via `storageState` in `playwright.config.ts`.
If any suite gets 401 or redirects to `/login`, re-run `auth:save` first.

---

## Schema map

`config/schema-map.json` is produced by Phase 0 and maps placeholder
tokens to real table names:

```json
{
  "PROJECTS":  "actual_table_name",
  "QUERIES":   "actual_table_name",
  "VIS_TREND": "actual_table_name",
  "CREDITS":   "actual_table_name"
}
```

All DB-* spec files import this map and substitute placeholders before
running SQL. Never hardcode table names in spec files.

---

## Swarm mode

When Malka says "swarm mode" or "write all Suite A specs":
- Spawn sub-agents per section (platforms, lifecycle, analytics, etc.)
- Each sub-agent writes its own `.spec.ts` file
- Sub-agents write tests only — they never drive the browser
- Run combined suite once with `npx playwright test` after all agents finish
