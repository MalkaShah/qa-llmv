# MalkaQA — LLMV E2E Test Runner

Black-box testing for LLM Visibility (LLMV) on `dashboard.searchatlas.com`.
No codebase access. URL + credentials + read-only DB only.

## Suites

| Suite | Cases | Execution | Run command |
|---|---|---|---|
| Phase 0 — DB discovery | 10 | once, before anything | `npm run db:discover` |
| Suite A — API | 106 | serial (credit-safe) | `npm run test:api` |
| Suite B — UI smoke | 110 | parallel (4 workers) | `npm run test:ui` |
| Suite DB — DB validation | 63 | serial | `npm run test:db` |
| Suite C — Deep E2E | ~30 | serial (state-dependent) | `npm run test:e2e` |

---

## First-time setup

### 1. Install dependencies
```bash
npm install
npx playwright install chromium
```

### 2. Fill in .env.db
The file already exists with DB credentials. Add the DB name once Phase 0 returns it:
```
LLMV_DB_NAME=   ← fill after running Phase 0
```

### 3. Save auth session
```bash
npm run auth:save
```
A headed browser opens. Log in manually if any challenge appears.
`auth-state.json` is saved — all suites use it automatically.

### 4. Run Phase 0 — DB schema discovery
Requires **Twingate active** (postgres-llmv must resolve).
```bash
npx ts-node tests/db/phase0-discovery.ts
```
This produces `config/schema-map.json` with real table names.
Fill `LLMV_DB_NAME` in `.env.db` using the value from `current_database()` in DB-000 output.

### 5. Run suites
```bash
npm run test:api    # Suite A — 106 API cases, serial
npm run test:ui     # Suite B — 110 UI cases, parallel
npm run test:db     # Suite DB — 63 DB cases
npm run test:e2e    # Suite C — deep E2E flows
```

Or everything in order:
```bash
npm run test:all
```

---

## Important rules

- **Suite A is always serial** — credit-integrity cases (run-analysis, double-charge) must never run in parallel
- **Twingate must be active** before any DB suite run — `postgres-llmv` only resolves via VPN
- **auth-state.json** expires — re-run `npm run auth:save` if you get 401s
- **config/schema-map.json** must exist before Suite DB runs — produced by Phase 0
- **DB is read-only** — no INSERT/UPDATE/DELETE ever runs in any test

## File structure

```

  .env.db                        ← credentials (never committed)
  .gitignore
  playwright.config.ts
  package.json
  tsconfig.json
  README.md
  auth-state.json                ← generated by save-auth (never committed)
  config/
    schema-map.json              ← generated by Phase 0 (committed — no secrets)
  helpers/
    save-auth.ts                 ← saves browser session
    global-setup.ts              ← verifies auth before suite runs
    db.ts                        ← shared pg pool (read-only)
  tests/
    api/                         ← Suite A — LLMV-API-* (106 cases)
    ui/                          ← Suite B — SMKT-LLMV-* (110 cases)
    db/
      phase0-discovery.ts        ← DB-000 to DB-009 (run once manually)
      runner.ts                  ← DB-010 to DB-079
    e2e/                         ← Suite C — deep flows (~30 cases)
```

## Failure classification

Every failure is labelled as one of:
- **API bug** — endpoint returns wrong data/status
- **UI bug** — page renders incorrectly or element missing
- **DB mismatch** — API response contradicts DB row
- **Test bug** — wrong selector, stale expected value

DB mismatch failures include the raw SQL result in the report.
